# Восстановление игрового архива из Google Sheets

Это копия **семи игровых таблиц**, а не полный резерв проекта Supabase.
Включены: users, drivers, races, race_driver_pool, predictions, results, result_changes в схеме public.
Паролей и таблиц auth здесь нет. Очки рассчитываются представлением scores из прогнозов и результатов.

## Сначала проверить

1. Использовать Node.js 22+ и код проекта с исправлением точного восстановления числовых ID.
2. Скачать COMPLETE-снимок: `node scripts/export/snapshot.js download "<название листа>" "<новая приватная папка вне репозитория>"`.
   Скрипт проверит порядок частей, SHA-256, набор таблиц и количество строк до сохранения файлов.
3. Схему брать из миграций коммита git_head в manifest.json; также нужно исправление restore-json.js.
4. Для восстановления public.users соответствующие UUID уже должны существовать в auth.users.
   Если проект потерян целиком, сначала восстановить авторизацию из отдельной полной локальной копии
   либо отдельно спроектировать перенос пользователей и связей. Создание новых аккаунтов с другими UUID
   без переноса ссылок не восстанавливает принадлежность прогнозов.

## Частичное восстановление в существующую базу

Пример предварительного сравнения выбранных таблиц:

```
node scripts/db/restore.js "<приватная папка>" public.predictions public.results public.result_changes
```

Без `--apply` игровые строки не заменяются, но скрипт создаёт служебную staging-таблицу для сравнения.
Не использовать этот шаг как полностью read-only аудит.

Сначала отдельно сохранить текущее состояние и проверить сценарий на изолированной базе.
Фактическая замена требует отдельного осознанного запуска с `--apply`; автоматически она не выполняется.
Передавать связанные таблицы совместно, учитывая внешние ключи. Скрипт упорядочит их по manifest.
Не запускать команду восстановления полной базы из scripts/db/RESTORE.md с этим архивом:
auth.users, auth.identities и другие служебные таблицы в нём отсутствуют.

Облачное сохранение и скачивание проверены; полноценное восстановление в отдельную новую базу
должно быть проверено отдельно. Никогда не тестировать восстановление на рабочей базе лиги.

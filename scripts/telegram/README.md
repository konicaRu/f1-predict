# Telegram-напоминания и итоги

## Досье трассы и погода (17.11.2026)

Открытие прогнозов собирается как единое Rich Message: графитовый баннер «Лига пророков»,
история трассы, прошлогодние времена, погода и прежняя кнопка Mini App. Напоминания используют
тот же стиль и свежий прогноз, без повторения истории. Гейт `raceweek_announced_at` сохранён.

- Jolpica: трасса сверяется по сезону, раунду и времени старта; до пяти последних победителей
  на том же `circuitId`, лучший круг гонки и поул именно предыдущего сезона. Условия сессий могут различаться.
- Open-Meteo: почасовая температура воздуха, максимум вероятности осадков и ветра в окне
  первых двух часов гонки. Максимум почасовых вероятностей не равен вероятности дождя за всю гонку.
  Прогноз обновляется при каждой отправке; часовые метки обрабатываются как UTC, даты показываются по МСК.
- OpenF1: свежая (до 24 часов) температура полотна на той же трассе, с названием сессии и временем.
  До первых сессий замера нет. Температуру грунта/воздуха не подставляем вместо асфальта.
- `data/circuits.json`: проверенные постоянные характеристики со ссылками. Полный реестр пока
  содержит Las Vegas. Для остальных трасс работают история и погода с общим баннером;
  длина, рекорд и схема появятся после добавления проверенной записи и PNG в `assets/`.
- Перспектива схемы не изображает настоящий рельеф. Перепад высот Лас-Вегаса не подтверждён,
  поэтому число не публикуется. Геометрия: Tomislav Bacinger, лицензия `data/GEOMETRY-LICENSE.md`.
- Внешние запросы ограничены 6,5 с. Недоступная часть подписывается; основной анонс продолжает работать.
- Если Telegram явно отклоняет Rich Message с 400/404, отправляется обычный HTML с тем же
  содержимым и кнопкой, без баннера. При сетевом таймауте/5xx автоматического fallback нет:
  первая отправка могла дойти. Живое отображение Rich Messages требуется проверить в тестовом чате.

Безопасный локальный предпросмотр (не читает `.env`/БД, не отправляет Telegram):

```powershell
node scripts/telegram/preview-dossier.js 2026 21
npm test --prefix scripts/telegram
```

Результат: `docs/mockups/telegram-dossier-live.html` и `.json`. В preview имена не
проголосовавших демонстрационные, кнопки отключены. SVG-исходники баннеров обновляются командой
`node scripts/telegram/render-dossier-banner.js`; PNG нужно перерендерить браузером при изменении SVG.

Метод Telegram: https://core.telegram.org/bots/api#sendrichmessage;
погода: https://open-meteo.com/en/docs; история: https://github.com/jolpica/jolpica-f1/tree/main/docs.

Ни preview, ни тесты не запускают `notify.js` как CLI. Команды ниже уже **отправляют** сообщения.

Автоматические сообщения в общий чат лиги: 🏁 RACE WEEK по понедельникам, напоминания о дедлайне

## Разовая настройка

1. В Telegram написать [@BotFather](https://t.me/BotFather) → `/newbot` → придумать имя и
   username бота (username должен заканчиваться на `bot`, например `f1predict_league_bot`).
   BotFather пришлёт токен вида `123456:ABC-DEF...` — это `TELEGRAM_BOT_TOKEN`.
2. Добавить бота в общий групповой чат лиги как обычного участника.
3. В чате написать команду `/id` (текст команды не важен, главное чтобы сообщение начиналось с
   `/` — обычные сообщения бот по умолчанию не видит из-за privacy mode).
4. Открыть в браузере (подставив свой токен вместо `<TOKEN>`):
   `https://api.telegram.org/bot<TOKEN>/getUpdates`
   В JSON-ответе найти `"chat":{"id": -100XXXXXXXXXX, ...}` — это отрицательное число и есть
   `TELEGRAM_CHAT_ID` (у групповых чатов id всегда отрицательный). Если `result` пустой —
   убедитесь, что отправили именно команду (начинается с `/`), а не обычный текст.
5. В GitHub-репозитории: **Settings → Secrets and variables → Actions → New repository secret**,
   добавить четыре секрета:
   - `TELEGRAM_BOT_TOKEN` — токен из шага 1
   - `TELEGRAM_CHAT_ID` — id из шага 4
   - `SUPABASE_DB_URL` — та же строка подключения, что в локальном `.env` (Dashboard → Connect →
     Session pooler, порт заменить на 6543 — если её раньше не заводили как GitHub secret)
   - `TELEGRAM_ADMIN_CHAT_ID` — личный Telegram chat_id владельца лиги (не общий чат!) — куда
     идут admin-уведомления о новых регистрациях/прогнозах/результатах. Узнать: написать боту в
     личку любое сообщение, начинающееся с `/`, затем открыть в браузере
     `https://api.telegram.org/bot<TOKEN>/getUpdates` и найти `"chat":{"id": ..., "type":
     "private", ...}` — это положительное число (в отличие от group id, который отрицательный).

## Проверка

Во вкладке **Actions** репозитория найти workflow «telegram-notify» → **Run workflow** →
выбрать режим (`raceweek` / `deadline` / `results` / `remind` / `autoresults` / `aiplayer` / `adminflush`) → запустить вручную. Проверить, что
сообщение пришло в чат (или что скрипт вывел «ничего не шлём», если сейчас нет подходящей гонки —
это нормальное поведение, не ошибка). После этого расписание сработает само.

Если workflow упал с ошибкой вида `... не найден в .env` — проверьте, что все четыре секрета
сохранены и не пустые в Settings → Secrets and variables → Actions.

## Локальный запуск (для отладки)

```bash
cd scripts/telegram
npm install
```

В корневой `.env` добавить `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` (см. шаги 1–4 выше);
`SUPABASE_DB_URL` там уже должен быть из настройки других `scripts/*`. Затем:

```bash
node notify.js raceweek   # или deadline, или results
```

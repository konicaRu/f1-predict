## 🎯 Видение

> F1 Predict — лёгкий способ для компании друзей завести закрытую лигу прогнозов на любое
> ранжируемое спортивное событие (не только Формулу-1) и голосовать там, где удобно — на сайте
> или прямо в мессенджере. Бесплатно навсегда, без рекламы и без гонки за ростом — растём
> органически, через друзей, которым понравилось.

Это направление, не обещание к сроку. Конкретные обязательства — в
[Roadmap по горизонтам](#-roadmap-по-горизонтам), и они заметно скромнее, чем видение целиком.

## 🧭 Принципы

| Принцип | Что это значит на практике |
|---|---|
| **Бесплатно навсегда** | Никаких платных тиров, донатов как обязательного элемента, рекламы. Расходы на инфраструктуру при росте — личные расходы автора, осознанный выбор |
| **Хобби-темп, без давления сроков** | Ресурс — Dim + Claude как агент, в свободное время. План должен переживать месяцы без движения, не протухать морально |
| **Органический рост** | Никакого маркетинга и виральных механик специально. Новые лиги и игроки — через «друг рассказал другу» |
| **Один движок, не N продуктов** | Мультиспорт — конфигурация общего движка прогнозов (событие → топ-N → очки), не форк кодовой базы под каждый вид спорта |

## 📍 Текущее состояние

MVP закрыт (2026-07-20), фазы 0–5 в проде: React-фронтенд + Supabase-бэкенд, RLS-защита,
Telegram-напоминания и автозабор результатов, ИИ-участник GridBot, бэкап в Google Sheets.

## 🧱 Стратегические треки

### 1 · Каналы — встретить игрока там, где ему удобно
Сайт остаётся основным, но голосование и просмотр статуса — ещё и через мессенджер. Приоритет —
**Telegram**: бот в чате лиги уже есть (`scripts/telegram/`), логичное продолжение — не только
слать напоминания, но и принимать прогноз. Практический аргумент: GitHub Pages из РФ требует
VPN, а Telegram — нет — доп. канал снимает часть трения.

**Как технически принимать прогноз в чате (проверено 2026-07-27):** голый чат с кнопками для
выбора 10 позиций по одной — рабочий, но неудобный вариант (drag-and-drop топ-10 в текстовом
диалоге — плохой UX). Правильный путь — **встроенные мини-приложения**: у Telegram (Mini Apps) и
у VK (VK Mini Apps) есть платформа для запуска полноценного веб-приложения прямо внутри
мессенджера — можно переиспользовать существующий React drag-and-drop UI почти без переделки,
а не собирать кнопочный флоу с нуля.

**Сравнение платформ:**

| Платформа | Можно принимать прогноз? | Как | Стоимость | Барьер входа |
|---|---|---|---|---|
| **Telegram** | ✅ приоритет №1 | Bot API + Mini App (реюз текущего UI) | бесплатно | нет — бота создаёт кто угодно |
| **VK** | ✅ кандидат №2 | Bots API (кнопки) или VK Mini App (реюз UI) | бесплатно | нет |
| **WhatsApp** | ⚠️ технически можно | WhatsApp Flows — многоэкранные формы в чате (дропдауны/радио) | с окт. 2026 даже сервисные сообщения в 24ч-окне становятся платными (utility-тариф) | нужна верификация Business-аккаунта через Meta — бюрократия |
| **MAX (RU)** | ❌ рассмотрели и отклонили | Есть офиц. Bot API + свои мини-приложения (dev.max.ru), технически ближе всего к Telegram/VK | бесплатно | **с августа 2025 публиковать ботов может только верифицированное юрлицо РФ** — физлицам/самозанятым/ИП нельзя. Прямой конфликт с «хобби-проект без юрлица» |

VK/WhatsApp — только если Telegram докажет спрос, не раньше (см. Roadmap). MAX технически
интересен (тот же паттерн Mini Apps), но не рассматриваем, пока проект остаётся хобби без
юрлица — это не техническое, а административное ограничение платформы.

### 2 · Мультиспорт — один движок, разные конфиги
Обобщить модель «гонка → топ-10 → очки за позицию» до «событие → топ-N → система очков».
Первый кандидат — **мотоспорт** (та же механика топ-N финиша, минимум изменений схемы). Второй
эшелон — виды спорта со счётом/победителем (**футбол**) — не конфиг поверх текущей формулы, а
отдельная система очков, честно более крупная работа.

### 3 · Вовлечённость и удержание
Уже работает: GridBot (соревновательный элемент), drift-chart (наглядность точности),
Telegram-итоги. Дальше — не абстрактные «фичи вовлечённости», а конкретные кандидаты (часть уже
была в общем беклоге `docs/plan.md` §15, здесь собраны в один трек с приоритетом):

- **Игровые механики из беклога:** доп. очки за поул/быстрый круг, «дабл-пойнтс» финал сезона,
  график динамики места в общем зачёте по ходу сезона. Дешёвые по объёму, понятная ценность —
  логичные первые кандидаты, когда дойдут руки до этого трека.
- **Season Wrapped** — персональная карточка по итогам сезона (в духе Spotify Wrapped): лучшая
  гонка, самый смелый прогноз, точность по сравнению с лигой. Реюзает уже посчитанные `scores` и
  `predictions`, ничего нового в бэкенде не нужно. Хорошо ложится на «органический рост» — такую
  карточку реально хочется кинуть в чат, в отличие от рекламы.
- **Сезонные «супергативы»** — авто-сгенерированные звания по итогам сезона («Оракул сезона» —
  больше всех точных попаданий, «Смельчак» — ставил на самых больших аутсайдеров), публикуются в
  Telegram по итогам последней гонки. Дёшево посчитать SQL-запросом поверх уже имеющихся `scores`.
- **Встроенная аналитика точности** (закрывает беклог-пункт «аналитика в Google-таблице» версией
  внутри продукта, а не ручным пересчётом в Sheets) — экран/раздел с точностью по игроку и по
  пилоту, тот же расчёт, который пользователь сейчас гоняет вручную во вкладке «анализ».

### 4 · Готовность к росту без паники
Free-tier Supabase далёк от лимитов при текущем масштабе (12 MB из 500 MB, см. обсуждение
ёмкости 2026-07-27). Инвайт-коды (миграция `0006`) уже дают контролируемый рост числа игроков
внутри лиги. Задача трека — не строить заранее лишнее, а иметь понятный триггер «когда
апгрейдить план» и не упасть тихо, как уже раз случилось с keep-alive (инцидент 2026-07-14).

Сюда же — снижение трения для новых лиг: сейчас всё закрыто инвайт-кодом, показать проект
знакомым «на пальцах» негде. Постоянно открытая **демо-лига без инвайта** (не текущая закрытая,
а отдельная витрина с демо-данными) даёт куда посмотреть, прежде чем звать друга регистрироваться
— это снижение трения, не маркетинг, поэтому не противоречит принципу «органический рост».

### 5 · GridBot 2.0 — развитие ИИ-состава
GridBot — уже готовая, редкая для фан-лиг фича (мало где есть живой ИИ-соперник). Логично не
останавливаться на одном экземпляре, раз инфраструктура (промпт → Gemini → валидация →
Telegram) уже есть и почти не требует нового кода:

- **Несколько ИИ-личностей с разными стратегиями** — не просто второй GridBot, а разный «характер»
  промпта (например, «ставит на фаворитов», «любит аутсайдеров», «строго по текущему чемпионату»).
  Каждый — тот же пайплайн `scripts/ai-player/`, другой текст промпта и, может, другое имя/аватар.
  Дешёвая вариативность и материал для обсуждения в чате «кто из ботов лучше угадывает».
  **Осторожно с квотами** — несколько ботов = несколько вызовов Gemini API за одну гонку, держать
  в уме бесплатный лимит (см. трек 4).
- **Пострасовый комментарий от ИИ** — короткий «репортаж» о гонке в Telegram по мотивам топ-10 и
  прогнозов лиги, отдельно от объяснения ставки GridBot. Тот же Gemini-вызов, другой промпт.

- Второй мессенджер-канал (VK или WhatsApp) — только если статистика использования

- Упрощённый путь «завести свою копию лиги» для другой компании друзей — не обязательно полный

- Демо-лига без инвайта — постоянная витрина с демо-данными, чтобы показывать проект новым
  людям без регистрации.

**Later (аспирационально, только по доказанному спросу)**
- Мультитенантность — несколько независимых лиг на одной инфраструктуре без ручного форка

## 📈 Метрики успеха (через 2 года)

| Метрика | Зачем именно эта |
|---|---|
| Минимум 2 активные лиги | Подтверждение, что формат воспроизводим не только для своей компании |
| Telegram-бот реально используется частью игроков | Сигнал, что доп. канал — не просто «для галочки» |
| Хотя бы один вид спорта, кроме Ф1, отыграл полный сезон в проде | Мультиспорт-гипотеза подтверждена на практике, не только в архитектуре |
| Ни одного простоя лиги из-за инфраструктуры за сезон | Рост не ломает то, что уже работает |
| Season Wrapped реально кидают в чат по итогам сезона | Органический рост работает не только в теории — люди сами делятся |

## ⚠️ Риски и открытые вопросы

- **Ресурс — хобби, не dedicated.** План должен переживать паузы; ре-сверка по контрольным
  точкам, не по календарю.
- **VPN-барьер для сайта из РФ** — реальное трение для органического роста «просто дай другу
  ссылку». Мессенджер-бот отчасти обходит проблему (трек 1).
- **Футбол — не конфиг, а отдельная фича.** Другая система очков (счёт/победитель, не топ-N) —
  закладывать это ожидание сразу, не недооценивать объём работы.
- **Мультитенантность — большой архитектурный скачок** (multi-tenant RLS, инфраструктура на
  несколько лиг). Не начинать без доказанного спроса.
- **Бесплатность при росте** — если реально появится много лиг, расходы на инфраструктуру
  (платный тир Supabase, Gemini-квоты на несколько GridBot) ложатся на автора лично — осознанно
  принятый компромисс.
- **MAX как канал закрыт административно, не технически.** С августа 2025 публиковать ботов в
  MAX могут только верифицированные юрлица РФ — если однажды появится юрлицо под проект, стоит
  пересмотреть (у MAX тот же паттерн Mini Apps, что у Telegram/VK).

## 🚫 Что принципиально не делаем

- Не строим коммерческий SaaS, не берём деньги с пользователей.
- Не гонимся за виральным ростом и маркетингом.
- Не поддерживаем несколько мессенджеров одновременно «про запас» — по одному, по факту спроса.
- Не начинаем мультитенантность без реального спроса от людей вне текущей лиги.

# Резерв архива в GitHub после результатов

**Запрос пользователя:** дополнительный резерв архива в GitHub сразу после получения результатов.

**Решение:** отдельный приватный `konicaRu/f1-predict-archive`, папка `archive/` с версиями JSON,
manifest и инструкцией восстановления. Публичный репозиторий приложения не содержит данных игроков.
Доступ runner — отдельным deploy key только к архивному репозиторию. Auth/пароли не выгружаются.

**Когда:** отдельное задание того же workflow после режима autoresults/results, в том числе при
ошибке отправки Telegram. Проверяется отпечаток results + result_changes; при отсутствии изменений
новый коммит не создаётся. Исправление результата создаёт новую версию. Ежедневный запуск и ручной
workflow_dispatch служат повтором после сбоев и охватывают ручные изменения результатов.

**Файлы:** `scripts/export/github-archive.js`, тест рядом; переиспользование snapshot.js;
`.github/workflows/github-archive.yml`, вызов из telegram-notify.yml, README экспорта.

- [x] Тесты: первый архив, повтор без изменений, исправленный результат, повреждённый manifest.
- [x] Сохранение исходного JSON с ID и SHA-256 в новой датированной папке, latest.json после проверки файлов.
- [x] Приватный репозиторий и отдельный deploy key; закрытый ключ только в GitHub Actions secrets.
- [x] Reusable workflow, вызов после autoresults/results; ошибки резервирования видны в Actions.
- [x] Первый настоящий прогон: проверить приватность, коммит и все контрольные суммы.

Восстановление в рабочую БД не запускать. Полный резерв авторизации по-прежнему хранится отдельно.

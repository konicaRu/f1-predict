# Archive Snapshots Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Выполнять последовательно, фиксируя проверки.

**Goal:** Сохранять восстанавливаемые версии игрового архива в выбранной пользователем Google-таблице.

**Architecture:** Новый Node.js CLI читает игровые таблицы в read-only repeatable-read транзакции. Каждый запуск пишет новый лист со статусом PREPARING, manifest и исходными JSON; после чтения обратно и проверки SHA-256 ставит COMPLETE. Скачивание возвращает manifest и JSON для существующего restore.js. GitHub Actions запускает копирование ежедневно в 10:15 МСК и вручную; активацию подтверждает реальный успешный запуск.

**Tech Stack:** Уже установленные pg, googleapis, node:test. Новые зависимости не нужны.

**Spec:** `docs/superpowers/specs/2026-11-17-archive-backup-audit.md`; пользователь выбрал Google Sheets со снимками по датам.

## Global Constraints

- Старые снимки не удалять, существующие вкладки отчёта не перезаписывать.
- Выгружать игровые таблицы с ID; auth-таблицы в Google Sheets не переносить.
- Неполные/повреждённые копии не отмечать COMPLETE и не скачивать как годные.
- Не выполнять восстановление в рабочую базу и не отправлять Telegram-сообщения.
- Не публиковать данные и credentials в git/Actions artifacts.

## Review Focus

- Обрыв загрузки: прежний снимок остаётся неизменённым, новый не COMPLETE.
- Повреждение/пропуск чанка: проверка запрещает публикацию и скачивание.
- Большие ID и Unicode: исходный JSON проходит round-trip без переформатирования.
- Потеря auth: инструкция явно описывает границу восстановления игрового архива.
- Cron существует только после публикации workflow; credentials должны быть настроены, нужен первый успешный запуск.

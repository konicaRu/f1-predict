## Цель

Автоматически сохранять архив гонок, прогнозы, идентификаторы и историю исправлений вне Supabase, сохраняя предыдущие версии. Уметь проверить копию и восстановить игровые данные после ошибки/потери базы.

## Варианты

1. **Снимки с датой в существующей Google-таблице — рекомендуемый первый вариант.** Доступ уже настроен, можно использовать текущий сервисный аккаунт. Новые снимки не перезаписывают старые; сохраняются исходные ID и JSON. Минусы: лимиты размера таблицы, доступ унаследован от текущего файла, полное восстановление авторизации требует отдельного резерва auth.
2. **Архивные файлы в отдельной приватной папке Google Drive.** Удобнее для полных копий и длительного хранения; нужно определить папку и постоянную авторизацию для фонового задания. Наличие Drive connector само по себе не даёт GitHub Actions постоянных credentials.

Пользователь выбрал Google Sheets — снимки с датой. Реализация готовится для существующей таблицы, без удаления старых снимков.

## Предлагаемые правила (для согласования)

- Запуск ежедневно и после появления/исправления результатов; ручной запуск для проверки. Точное расписание выбрать в техническом плане.
- Снимать согласованное состояние игровых таблиц, а не независимые запросы в разные моменты времени.
- Минимальный архив: `public.users`, `drivers`, `races`, `race_driver_pool`, `predictions`, `results`, `result_changes`. Отдельно контрольная выгрузка `scores`; очки пересчитываются правилами из миграций.
- Сохранять реальные идентификаторы, сезон, даты UTC, JSON-структуры и связи; не ограничиваться именами и кодами пилотов.
- Manifest: время снимка, версия формата, git-коммит и список миграций, количество строк, SHA-256, статус проверки.
- Опубликованной считать копию только после чтения обратно и проверки содержимого/контрольных сумм. Незавершённый снимок не заменяет последнюю годную копию.
- Предыдущие снимки сохранять; срок хранения и ограничения объёма согласовать перед автоматическим удалением. По умолчанию ничего не удалять.
- Не выгружать в публичный репозиторий, Pages, логи или общедоступные Actions artifacts персональные данные, auth-таблицы и ключи.
- Полный резерв `auth.users`/`auth.identities` содержит секретные сведения: при выборе облачного хранения для него нужен отдельный приватный защищённый путь. Игровой архив без auth не обещает восстановить вход пользователей в новый проект одной командой.
- Для восстановления сначала локально проверить целостность и показать план/diff. Запись в живую базу — отдельное явное действие пользователя; текущая проверка не включает восстановление.
- Проверить восстановление на изолированном тестовом окружении, без Telegram-отправок и изменения рабочих прогнозов.
- Ошибки резервирования должны быть видны в статусе задания; если потребуется уведомление администратору, включать его только в рамках согласованной настройки.

# Автопроверка состава пилотов гонки + ручная правка из Админки (дизайн)

Дата: 2026-09-03
Статус: согласован, готов к плану
Сверено с `docs/constitution.md` (§2 RLS-first — пул уже открыт админу на запись политикой
`pool_write`, новых грантов не требуется; §4 инфраструктура — GitHub Actions, тот же паттерн, что
Telegram/autoresults; §5 процесс; §6 YAGNI — не строим общий «статус пилота», только то, что нужно
для этого сценария).

## 1. Повод

Гран-при Италии (round 13): Аджар сломал запястье, его заменяет Цунода — которого вообще не было в
`drivers` (у Jolpica он не попал в `driverStandings`, места в сезоне не было). Почин сделан вручную
через `runner.js sql` прямо во время гонки: добавлен в `drivers`, добавлен в `race_driver_pool`
открытой гонки, добавлена колонка `race_driver_pool.out_reason` и проставлена у Аджара, на фронте
бейдж DNF. Это разовая ручная операция в обход всех UI — эта спека строит нормальный путь для
следующего раза.

Ключевая находка: `race_driver_pool` — снимок `drivers where active`, снимается один раз при
`open_race()` (сейчас автоматом в начале недели, `ensureCurrentWeekOpen()`) и дальше никогда не
обновляется. Замена, объявленная после этого момента, физически некуда вписать — ни в прогноз, ни (что
хуже) при последующем заносе результата, `set_race_result` тоже валидирует состав против пула.

## 2. Решения (из брейншторма)

- **Ручная правка — основной путь, автосинк — подстраховка.** Jolpica обычно узнаёт о заменах позже
  реальных новостей — 100%-автоматика ненадёжна. Админ, узнав новость сам, должен быстро поправить
  пул из Админки; автосинк лишь подхватывает то, что источники уже успели показать.
- **Источник для замены — только существующие `drivers`** (включая неактивных), без формы «вписать
  совсем нового пилота от руки» — резервисты почти всегда уже когда-то дебютировали и есть в
  справочнике. Ручной SQL-инсерт нового пилота (как сегодня с Цунодой, которого и правда нигде не
  было) остаётся редким крайним случаем вне этой спеки — `importDrivers()` рано или поздно подтянет
  его сам, как только Jolpica обновит `driverStandings`.
- **Расписание проверки — переиспользуем существующие крон-слоты**, отдельного нового расписания не
  заводим: Пн 10:05 (`raceweek`), Ср 10:05/19:05 и Чт 10:05/19:05 (`deadline`, все — до дедлайна
  20:00 UTC / 23:00 МСК чт).
- **Два источника с разным порогом доверия, а не поиск третьего.** Jolpica (сезонный состав) уже
  используется в проекте как основной; OpenF1 (даёт состав по сессии конкретного уикенда) — уже
  используется как фолбэк для `autoresults`. У OpenF1 есть известное ограничение — данные по сессии
  появляются, только когда она уже началась (Пт+, то есть обычно после дедлайна), до этого он молчит.
  Третий источник не заводим (нет другого бесплатного API того же качества, а скрейпинг официального
  сайта — избыточный риск для хобби-проекта); молчание OpenF1 — не блокер, просто более слабое
  подтверждение.
- **Оба чата получают уведомление при любом обнаруженном изменении** — и автоматическом (крон), и
  ручном (Админка). Админский — подробное (что нашли, откуда); общий — короткое и по делу.

## 4. Уведомление в оба чата — переиспользуем `admin-notify`, а не изобретаем очередь

Перечитал `supabase/functions/admin-notify/index.ts` перед тем, как писать эту секцию — он устроен
проще, чем я сначала предположил, и решает ровно эту задачу «из браузера в Telegram» без всякой очереди
на постоянной основе:

- Фронтенд уже дёргает эту Edge Function напрямую через `supabase.functions.invoke('admin-notify', ...)`
  с publishable/anon-ключом — **осознанно без второй авторизации** (комментарий в коде: риск принят на
  ревью, худшее — спам в приватный чат админа, не утечка данных). Секретный `TELEGRAM_BOT_TOKEN`
  остаётся только на сервере (env функции), фронт его не видит.
- Функция шлёт в Telegram сразу (кроме тихих часов 22:00–10:00 МСК для админ-чата — тогда в очередь
  `admin_notification_queue`, забирается утренним `adminflush`).

Для двух чатов ничего конструктивно нового не нужно, кроме нового `event_type: 'pool_change'`:
- **Автоматическая проверка (`checkDriverPool()` в `notify.js`)** — это Node-скрипт, `TELEGRAM_BOT_TOKEN`
  у него и так есть в `.env` (как у остальных режимов) → шлёт в оба чата напрямую через уже
  существующий `sendTelegram()`/`sendTelegramPhoto()` из `scripts/telegram/lib.js`, Edge Function ему не
  нужна вообще.
- **Ручная правка в Админке (`AdminPool.tsx`)** — это браузер, токена нет → единственный путь, ради
  которого и нужна доработка `admin-notify`:
  - Новая ветка `event_type: 'pool_change'` строит текст (`🔄 {race_name}: {driver_name} ({code})
    {added ? 'добавлен в состав' : 'отмечен как не участвует' + reason}`).
  - Уходит в **админский** чат по уже существующей логике (сразу или в очередь, если тихие часы —
    без изменений).
  - Уходит в **общий** чат (`TELEGRAM_CHAT_ID`, новый env-секрет функции наряду с уже существующим
    `TELEGRAM_ADMIN_CHAT_ID`) **сразу и безусловно**, без тихих часов и без очереди — редкое и важное
    для игроков сообщение, откладывать на утро не нужно (в отличие от «зарегистрировался участник»/
    «кто-то поставил прогноз», которые и породили правило тихих часов).

- **`AdminPool.tsx`**: ручной smoke — открыть страницу для Italian GP (там уже реальные данные из

- **OpenF1-путь** нельзя протестировать по-настоящему до начала уикенда (данных ещё нет) — проверяем
  только что функция корректно возвращает `null` без ошибки, когда сессий в окне нет (текущая ситуация
  прямо сейчас, реальный вызов).
- **`buildMessage('pool_change', ...)`**: расширить `supabase/functions/admin-notify/format.test.ts`
  (уже есть, тот же паттерн, что для `registration`/`prediction`/`result`) — added/out варианты текста.
- **Реальный smoke `admin-notify`**: вызвать функцию локально/curl с `event_type: 'pool_change'`,
  убедиться что уходит два сообщения (в оба чата, второе — в тестовый чат, не в боевой общий, на время
  проверки подменить `TELEGRAM_CHAT_ID`).

## 6. Вне скоупа

- Форма «вписать нового пилота от руки» (когда его вообще нет в `drivers`) — редкий случай, остаётся
  через `runner.js sql`, как сегодня с Цунодой.
- Третий источник данных сверх Jolpica+OpenF1.
- Вторая авторизация поверх anon-ключа для `admin-notify` — уже осознанно не сделана в существующей
  функции (см. §4), этой спекой не меняется.
- Автоматическое снятие `out_reason` / удаление пилота из пула — если новость окажется неверной,
  правится той же кнопкой в Админке вручную.
